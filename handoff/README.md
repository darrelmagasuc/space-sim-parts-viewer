# handoff/

Material for the Godot game's coding agent: how to import the parts, and a spec for porting Vehicle Creation. **Start with [`AGENT_HANDOFF.md`](AGENT_HANDOFF.md).**

- [`AGENT_HANDOFF.md`](AGENT_HANDOFF.md): project, repo layout, conventions, Godot import, workflow, start-here checklist
- [`CONVENTIONS.md`](CONVENTIONS.md): copy of the authoritative modelling conventions
- [`parts_manifest.json`](parts_manifest.json): every part, variant and released interior, with `manifest_version`, `generated_at` and sha256/`content_hash` per id (the schema is in its `schema` key); generated by `tools/build_manifest.py`
- [`CHANGELOG.md`](CHANGELOG.md): the release history (`parts-vX.Y.Z` tags); releases are published only on request
- [`vehicle_creation_spec.md`](vehicle_creation_spec.md): builder spec and GDScript porting guide
- [`test_vehicles/`](test_vehicles/): example crafts with expected world-space results
- [`materials_library.json`](materials_library.json): shared low-poly material library
- `tools/`: `build_manifest.py`, `build_test_vehicles.mjs` + `test_vehicle_defs.mjs`, `reference_builder.py`, `sync_to_godot.py` (hash-based re-sync), `import_interiors.py` (copies released interiors into `models/interiors/`), `publish_update.py` (cuts a release: diff, bump, changelog, tag), `part_info.json` (catalogue text cache used by the manifest build)

Before each work session the game agent compares `manifest_version` with its last sync and reads the CHANGELOG (see AGENT_HANDOFF.md §13). Change requests go to GitHub Issues with the label **`game-request`**.
